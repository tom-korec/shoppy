| D-50 | Entries are listed in **id order**, and the app chooses entry ids as **UUIDv7** (time-ordered; the API rejects other versions). No `position` column on entries                                                 | Claude, during Phase 2                     |
| D-51 | A scope's whole catalog is loaded once and searched on the device (catalog search, category filter, quick-add suggestions, accent- and case-insensitive). | D-52 | Size limits against runaway data on the free database: 100 categories, 2,000 items and 200 lists per scope, 500 entries per list, 500 ids per bulk request, history pages of at most 100 records, at most 200 records in the recent section                                                                                                                                                                                                                                                                                                                                      | Claude, during Phase 2                     |
| D-53 | Promoting a one-time entry whose name already exists in the catalog links it to that item instead of failing. Restored and re-added entries go to the end of their group                                                                                                                                                                                                           | Claude, during Phase 2                     |
| D-54 | API details: the recent-history section is `GET /lists/:id/history/recent` (not `?recent=true`); the History screen pages with a cursor; shopping mode uses `PATCH /entries/:id {isChecked}` and `POST /lists/:id/finish-shopping`. One curated set of 63 Lucide icons serves both lists and categories                                                                                                                                                                                                                                                                          | Claude, during Phase 2                     |
| D-55 | From the Phase 2 security review: each user may add at most **3,000 rows a day** (entries, history records, items, lists, categories; in memory per instance like D-37), so one account can't fill the free database. Size limits (D-52) lock the list or user row before counting, so parallel requests can't overshoot them. Moves into or out of history fail with 409 if a parallel request already moved the same rows (no duplicates). Same-name item lookups compare `lower(name)` exactly (no `ILIKE` wildcards). The app only accepts a UUID as `:listId` in its routes | Claude, during Phase 2                     |
